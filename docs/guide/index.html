🖥️ MyDesk — the desktop half

MyDesk is a Nix + Home Manager desktop that boots straight into Hyprland with a Quickshell bar and the hub service already running in the background.

Boot chain

greetd + tuigreet → start-hyprland → Hyprland (64 Lua binds) → Quickshell bar → tui-op-hub.service on :31415

The desktop locks but never sleeps (suspend disabled at the idle-manager level) — leave it running.

The bar

  • Left island — your workspaces (each monitor gets its own block of ten).
  • Center pill — the focused window's title, always in view.
  • Right island — network · bluetooth · audio · battery · settings gear. The audio pill opens an output-device picker (✓ on the active sink, a mute row, per-device click-to-switch); the scroll wheel still changes volume.

Keybinds

SUPER+Return terminal · SUPER+Q close · SUPER+T hub TUI · SUPER+H cheat-sheet · SUPER+SHIFT+R restart bar · SUPER+digits workspaces

Settings — 14 sections

Theme · KDE & Dolphin · Bar · Idle & Lock · Hyprland · Terminal · Defaults · Packages · Programs · System · Devices · Sync · Distro · Nix

  • Theme — pick an accent; matugen regenerates nine outputs at once (kitty, gtk3, gtk4, ghostty, nvim, tmux, zathura, starship, the bar's theme.json). The bar re-colors live.
  • Packages — three tiers side by side: your mydesk nix profile, the declarative user-packages.nix, and the distro manifest — each with an “in hub →” deep link.
  • Devices — numlock-on-login, tap-to-click, and friends; persisted into Hyprland's runtime config.
  • Nix — garbage collect (user and system), optimise the store, browse generations.
  • Keys — SSH/GPG card with live status: remember a passphrase, rescan, push — the card refreshes when the terminal task finishes.

Troubleshooting

  • mydesk-health — one sweep over disk, services and shell sanity.
  • mydesk-fault capture — screenshot + log bundle into the repo's faults/ folder for a bug report.
  • SUPER+SHIFT+R — restart the bar if it misbehaves (compositor untouched).
⇄

🤝 How mydesk and the hub fit together

The hub is the surface, mydesk is the machinery.

Shell → hub (buttons)

Settings → Packages: every tier card has an “in hub →” button launching tui-op-hub --section pkg; the Distro card has “install in hub”. No flags to remember.

Hub → mydesk (declarations)

Search result[d] declare writes to
[nix]mydesk-pkg addgh → user-packages.nix
[pacman] / [aur]mydesk-distro add → distro manifest
[flatpak] / [snap]mydesk-apps record → apps manifest
[src] owner/repomydesk-repro add → [[src]] row

r on Packages runs mydesk-repro capture — snapshotting imperative installs back into the manifests (also weekly on a timer). Declare here, mydesk-rebuild everywhere: devices converge.

Shared secrets & keys

One vault: the hub service (:31415) encrypts with ~/.local/state/mydesk/secrets-key. Secrets tab I imports from ~/.ssh, S offers keys to ssh-agent, y copies the public half — the same keys mydesk-keys manages.

Plugin trust

The service runs the bundled mydesk.core plugin: Plugins tab → a approve → H headless trust — after that it auto-approves on boot.

🤖

Drive it with an AI agent (MCP)

MyDesk ships an opencode config registering two local MCP servers, so your AI agent can observe the whole machine:

ServerTools
tui-op-hubquery_entities, get_secret, system_health, recent_errors, host_facts, run_mydesk
mydeskhost_facts, mydesk_health, recent_errors, fault_list/latest, repro_status, distro_status, pkg_profile, keys_list (names only, never values), sync_status, run_mydesk

run_mydesk is allow-listed: only read/status commands pass (health, repro status, distro status, pkg list, keys list, sync status, updates…). An agent can diagnose, not mutate.

Try it: open opencode and ask “what's drifting on this machine?”.

📖 Quick start

  1. Boot → tuigreet → tui-op-hub (or SUPER+T).
  2. Log in once — profile and vault persist.
  3. ? in any screen shows the live cheat-sheet.
  4. Install something: Packages → / query → Enter → i or d.
  5. Change the theme: bar gear → Theme → pick an accent — everything re-colors.
