🤝 How mydesk and the hub fit together

The two halves share one declarative spine: the hub is the surface, mydesk is the machinery. Here is every connection:

Shell → hub (buttons)

Open the MyDesk settings (bar gear) → Packages: every tier card (mydesk profile, declarative user-packages.nix, distro manifest) has an “in hub →” button that launches tui-op-hub --section pkg — same for the Distro card’s “install in hub”. You never have to remember flags.

Hub → mydesk (declarations)

Inside the hub’s Packages section, the confirm popup has two paths: i installs immediately, d declares — writing into the mydesk git-tracked manifests on this host:

Search result[d] declare writes to
[nix]mydesk-pkg addgh → user-packages.nix
[pacman] / [aur]mydesk-distro add → distro manifest (repo + AUR tiers)
[flatpak] / [snap]mydesk-apps record → apps manifest
[src] owner/repomydesk-repro add → [[src]] row (clone + build)

r on Packages runs mydesk-repro capture — snapshotting whatever you installed imperatively back into the manifests (this also runs weekly on a timer). Declare on this machine, mydesk-rebuild elsewhere: every device converges.

Shared secrets & keys

One vault, one key. The background service (tui-op-hub.service, port 31415) reads its encryption key from ~/.local/state/mydesk/secrets-key. The Secrets tab manages the same SSH keys mydesk-keys does: I imports from ~/.ssh, S offers them to ssh-agent, y copies the public half. The keygen flow (k) vaults what it creates.

Plugin trust

The hub service runs the bundled mydesk.core plugin. Approve it once: Plugins tab → a (approve) → H (headless trust) — after that the service auto-approves it on boot and the dashboard keeps working in the background.

🤖 Drive it with an AI agent (MCP)

MyDesk deploys an opencode config (opencode.jsonc) that registers two local MCP servers — so an AI coding agent can observe and report on the whole machine:

ServerTools
tui-op-hubquery_entities (search the knowledge vault), get_secret, system_health, recent_errors (journal tail for bug hunting), host_facts, run_mydesk
mydeskhost_facts, mydesk_health, recent_errors, fault_list/latest, repro_status, distro_status, pkg_profile, keys_list (names + flags, never values), sync_status, run_mydesk

run_mydesk is allow-listed — only status/read commands pass (health, repro status, repro capture --dry-run, distro status, pkg profile/declarative/list, keys list, sync status, apps status, updates); anything else (e.g. rm -rf /) is rejected. The agent can diagnose, not mutate.

Try it: open opencode and ask “what’s drifting on this machine?” — it runs repro status + distro status and answers with facts.
